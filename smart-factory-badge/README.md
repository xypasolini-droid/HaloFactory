# 智慧工厂工牌：三模块最小落地版

这个工程已经把你跑通的三模块测试代码落成一个可操作的智慧工厂工牌 MVP：170×320 竖屏显示任务卡，单个 KY-004 完成任务切换、问题分类、完工品质确认，外接灯给出红/绿业务状态，所有正式动作同时输出一行串口 JSON。

本版本严格只依赖三个功能模块：

1. ESP32-1732S019（含板载 1.9 寸 ST7789）
2. 你当前已经接好的共阴 LED 模块
3. KY-004 按键

没有加入振动马达、电池、触摸屏、传感器、Wi-Fi 后台或其他功能模块。代码里的四条任务是离线演示数据。

## 已实现的工牌闭环

- 上电默认显示概念图中的第 `2/4` 项：`装左门板`，剩余 `18` 件。
- 短按进入四类问题上报：`有坏件 / 缺材料 / 机器坏 / 有危险`。
- 双击切换下一张任务卡，替代概念图里当前硬件无法执行的“滑动换任务”。
- 长按 2 秒进入完工品质确认；必须再短按选择 `合格 / 不合格`，并再次长按 2 秒才提交。
- 合格时剩余数量减 1，绿灯双闪持续 5 秒，串口输出品质与完工事件。
- 不合格或问题上报后进入锁定页，红灯快闪；普通按键操作不能解除。
- 选择页 10 秒无操作自动返回，不产生业务事件。
- 启动时依次点亮红灯、绿灯，便于第一次实机核对 R/G 映射。
- 每次流程或品质选项改变时，串口输出一行 `# FLOW state=... quality=... led=...`，用于核对屏幕流程与灯态是否同步。

## 接线：以你本轮明确描述为准

| 功能 | ESP32-1732S019 | 说明 |
|---|---:|---|
| LED `R` | GPIO15 | 红色业务灯 |
| LED `G` | GPIO16 | 绿色业务灯 |
| LED `B` | GPIO17 | 已接线，但本方案始终保持关闭 |
| LED `-` | GND / 面包板负极 | 共阴接法 |
| KY-004 最左 `S` | GPIO2 | 程序按“按下为 LOW”读取 |
| KY-004 中间 `+` | 3.3V / 面包板正极 | 不要改接 5V |
| KY-004 最右 `-` | GND / 面包板负极 | 与 ESP32 共地 |

板载屏幕继续使用你已经编译成功的参数：

| ST7789 信号 | GPIO |
|---|---:|
| MOSI | 13 |
| SCLK | 12 |
| DC | 11 |
| CS | 10 |
| RST | 1 |
| BL | 14 |

屏幕保留 `170×320`、IPS 和 `35` 像素列偏移；旧测试程序的 `rotation=3` 实际得到 `320×170` 横屏，本工程改为 `rotation=0` 的 `170×320` 竖屏。如果屏幕内容上下颠倒，只把 `src/main.cpp` 顶部的 `TFT_ROTATION` 从 `0` 改成 `2`，不要改变 35 像素偏移。

### 关于 LED 型号名称的关键说明

标准 KY-029 通常是三针红/绿双色模块，并没有 `B` 引脚；你描述的 `R/G/B/-` 四根线以及压缩包里的名称更接近 KY-009/四针共阴 RGB 模块。这个工程不依赖型号名称，而是严格按你给出的四根实际接线驱动，并只使用红、绿两色。

压缩包源码的注释写的是 `R=15 / G=16`，但实际宏把二者写成了 `R=16 / G=15`。本工程已经按你本轮明确接线修正为 `R=15 / G=16`。上电会先红后绿各亮约 0.22 秒；如果实物显示顺序反了，只交换 `PIN_LED_RED` 和 `PIN_LED_GREEN`，不要修改业务状态机。

如果实物真的是只有三针的标准 KY-029，请不要照搬四线表，应先按模块丝印和共阴/共阳类型重新确认接法。

> 若模块每个颜色通道没有可靠的板载限流电阻，应在 R、G（以及未来若使用 B）支路各串联一个约 220–330Ω 的限流电阻。电阻是必要保护件，不是新增功能模块。

## 编译与上传

工程使用 PlatformIO，目录结构如下：

```text
smart-factory-badge/
├── BUILD_REPORT.md
├── firmware/           # 已实际编译的四个烧录文件及地址说明
├── platformio.ini
└── src/
    └── main.cpp
```

在 VS Code + PlatformIO 中打开整个 `smart-factory-badge` 文件夹，然后执行：

```bash
pio run
pio run -t upload
pio device monitor -b 115200
```

配置沿用了测试包的 `esp32-s3-devkitc-1`、USB flags、Arduino-ESP32 `3.1.3` / ESP-IDF `5.3.2` 和 Arduino_GFX `1.6.7`。这里明确使用与原 ZIP 构建环境一致的 pioarduino Core 3.x 平台；标准 PlatformIO `espressif32` 当前仍会解析到 Core 2.x，与 GFX 1.6.7 不兼容。

工程使用完整中文点阵字体，因此 `platformio.ini` 设置了 `16MB` Flash 和 `huge_app.csv`。这个通用分区给单个固件约 3MB 空间，不支持 OTA，也不会自动利用 16MB Flash 的全部剩余容量；对当前本地 MVP 足够。以后加入 OTA、图片资源或持久化队列时，应改为项目自带的 16MB 分区表。

本交付已经实际执行 `pio run` 并通过。RAM、Flash、依赖版本和二进制 SHA-256 见 `BUILD_REPORT.md`；`firmware/` 中也保留了本次构建的 bootloader、分区表、boot_app0 和 app 固件。正常使用仍建议从源码执行 PlatformIO upload。

## 单键操作

| 当前页面 | 短按 | 双击 | 长按 |
|---|---|---|---|
| 任务页 | 进入问题上报，不立即上报 | 下一任务 | 2 秒进入完工确认，不立即完工 |
| 问题选择 | 下一类问题 | 取消返回 | 2 秒确认上报并锁定 |
| 品质选择 | `未选择 → 合格 → 不合格` | 取消返回 | 2 秒提交所选结果 |
| 异常/不合格锁定 | 无效 | 无效 | 演示构建中 8 秒本地复位 |
| 完成页 | 无效 | 无效 | 无效；5 秒后自动返回 |

短按会等待最多 350ms，以判断是否还有第二下。少于 50ms 的脉冲按抖动处理；按住 0.7–2 秒但未达到确认阈值时不会误当成短按，屏幕会提示“未确认，请按到100%”。

## LED 语义

默认使用现场容易辨认的交通灯语义；灯态直接由当前业务状态计算，不再作为独立颜色演示运行：

| 屏幕/业务状态 | 实物灯态 | 含义 |
|---|---|---|
| 任务页 `WORKING` | 绿灯常亮 | 正常生产，当前任务可操作 |
| `发现问题` 选择页 | 红、绿同时慢闪，形成黄灯 | 正在选择问题，尚未正式上报 |
| `完工确认` 尚未提交 | 红、绿同时双脉冲，形成黄灯 | 正在选择品质，尚未正式提交 |
| 问题已上报 / 品质不合格锁定 | 红灯快闪 | 异常结果已经提交，任务锁定 |
| 本件合格完成 | 绿灯双闪，持续 5 秒 | 完成结果已经正式提交 |
| 蓝色通道 | 始终关闭 | 当前业务不定义蓝灯语义 |

品质页短按选中“合格”或“不合格”时仍保持黄灯：选中只是候选值，只有再次长按 2 秒正式提交后，才会进入绿灯完成或红灯锁定，防止工人把“已选择”误认为“已生效”。

如果必须严格沿用概念图的“待完成红灯”，可把 `RED_MEANS_TASK_PENDING` 改成 `true`；异常锁定仍保持红灯快闪。默认值为 `false`，即生产中绿灯常亮。

黄灯由红、绿两个通道同时点亮形成。不同模块可能呈现偏黄、偏橙、偏红或偏绿；只要两个通道都在同一节拍闪烁，状态逻辑就是正确的。R、G 两个通道必须各自具备板载或外串限流电阻。

颜色不是唯一提示：屏幕会同时显示文字状态，避免只凭红/绿色判断。

## 串口业务事件

只有“确认提交”才产生业务事件。示例：

```json
{"schema_version":1,"event_id":"BADGE-DEMO-01-1234ABCD-000002","badge_id":"BADGE-DEMO-01","worker_id":"W102","line_id":"ASSEMBLY-1","task_id":"WO018-OP20","task_index":2,"task_count":4,"remaining":18,"event_type":"EXCEPTION_RAISED","state":"EXCEPTION_LOCKED","payload":{"category":"MATERIAL_SHORTAGE"},"boot_id":"1234ABCD","device_sequence":2,"device_ms":18253}
```

当前会输出：

- `DEVICE_BOOT`
- `EXCEPTION_RAISED`，分类值为 `DEFECTIVE_PART / MATERIAL_SHORTAGE / MACHINE_FAILURE / SAFETY_HAZARD`
- `QUALITY_SUBMITTED`，结果为 `PASS / FAIL`
- `PART_COMPLETED`
- 当剩余数降到 0 时输出 `TASK_COMPLETED`

双击换任务、取消选择和选择超时只输出以 `#` 开头的调试行，不伪造业务事件。

流程灯追踪行同样以 `#` 开头，不是业务事件。例如：

```text
# FLOW state=WORKING quality=NONE led=WORKING_GREEN_SOLID
# FLOW state=REPORT_SELECT quality=NONE led=ISSUE_SELECT_YELLOW_SLOW
# FLOW state=QUALITY_SELECT quality=PASS led=QUALITY_AWAIT_YELLOW_DOUBLE
# FLOW state=EXCEPTION_LOCKED quality=NONE led=LOCKED_RED_FAST
# FLOW state=COMPLETE quality=PASS led=COMPLETE_GREEN_DOUBLE
```

## 演示模式与正式锁定边界

`DEMO_MODE=true` 是为了只用这三个模块也能反复演示：锁定页持续按 KY-004 8 秒会回到当前任务。串口只打印 `# DEMO_RESET`，它不是正式的 `EXCEPTION_RESOLVED` 管理事件。

现场版本必须把 `DEMO_MODE` 改成 `false`。此时问题上报和品质不合格不能由工人本机解除，只能由未来后台下发 `EXCEPTION_RESOLVED / TASK_REASSIGNED` 等管理命令。当前离线版本还没有后台命令通道，正式联机前不要把它当作生产安全报警系统。

## 建议的实机验收顺序

1. 上电时确认屏幕是竖向、没有裁切，LED 按“红 → 绿”顺序自检。
2. 任务页应显示 `装配一线 2/4 / 装左门板 / 还要18件`，绿灯常亮。
3. 短按进入“发现问题”，确认红、绿同时慢闪形成黄灯；再连续选择 20 次，确认每次只移动一次选项，没有重复事件。
4. 做 10 次长按，确认达到 100% 才触发，松手后不会补发短按。
5. 在问题选择中用双击取消，确认串口没有 `EXCEPTION_RAISED`。
6. 选择“缺材料”并长按提交，确认红灯快闪、屏幕锁定，串口恰好输出一次对应事件。
7. 演示模式下长按 8 秒复位；回到任务页后长按进入完工确认，确认黄灯双脉冲。
8. 不选择品质直接长按，必须只提示选择，不能完工；短按选中合格或不合格时仍保持黄灯，表示尚未提交。
9. 选择“合格”并长按，确认剩余数 `18 → 17`、绿灯双闪持续 5 秒，依次输出 `QUALITY_SUBMITTED/PASS` 和 `PART_COMPLETED`。
10. 选择“不合格”并长按，只允许进入品质锁定，绝不能输出 `PART_COMPLETED` 或 `TASK_COMPLETED`。

## 当前验证边界

三个模块可以验证工人任务显示、单键交互、问题分类、人工品质结果、锁定规则、红绿反馈和结构化业务事件；不能验证自动质量检测、真实人员身份、物料定位、无线后台、断网补传、电池续航、振动反馈或工业安全联锁。

量产前还需要：可靠的事件 ID、NVS 持久化队列、真实时间同步、网络重试与服务端幂等、后台任务下发、管理端解除锁定、权限和现场耐久测试。`device_ms` 只是本次开机后的毫秒数，不能当作真实时间。
