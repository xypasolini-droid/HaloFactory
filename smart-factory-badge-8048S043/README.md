# 智慧工厂工牌：ESP32-8048S043 竖屏触摸版

本工程已将原先面向 ESP32-1732S019、170×320 SPI 屏的智慧工牌代码，适配为 ESP32-8048S043C 的板载触摸竖屏版。RGB 面板仍按物理/原生 800×480 时序扫描，界面经软件 `rotation=1` 后使用 480×800 逻辑画布。任务、问题上报、品质确认、锁定和串口 JSON 事件保留，交互改为板载 GT911 触摸，业务灯改为屏幕内状态灯。

最终方案不使用任何外接 KY-004 或 RGB LED，不需要连接 P2/P3/P4 排针。GPIO11、GPIO12、GPIO13 和 GPIO17 在本程序中均不作为业务输入/输出，不对外接线。

已在实物板上完成：

- ESP32-S3 rev 0.2、16 MB Flash 和 8 MB OPI PSRAM 识别。
- 物理 800×480 RGB565 帧缓冲创建，单帧 768,000 字节。
- `rotation=1` 后的 480×800 竖屏逻辑尺寸和背光 GPIO2 启动日志。
- GT911 以 100 kHz I²C 轮询模式启动，不依赖 INT。
- 实机识别 GT911 `address=0x5D`、`product=911`、`firmware=0x1060`、原始范围 `480×272`。
- 最新触摸版编译成功、已烧录启动，进入 `WORKING` 并发出 `DEVICE_BOOT` 事件。
- 触摸方向正确；“下一任务”可连续切换；问题页可进入并取消返回；品质页可选择 PASS。
- 静止长按 1,000 ms 已成功提交 PASS，串口产生 `QUALITY_SUBMITTED` 和 `PART_COMPLETED`；切页后的 release suppression 已证明不会把同一次触摸穿透到新页面。
- 最终四段镜像已逐段执行 `verify_flash`，全部返回 `digest matched`，并已重算 SHA-256。

尚待完成的实机验收是：四种问题分类逐一选择及异常 1 秒长按上报、FAIL 提交后的锁定流程、锁定页 8 秒演示复位，以及所有屏内状态灯颜色/动画的人工目视确认。已完成的 PASS 路径不能替代这些剩余分支。

## 屏幕与存储配置

目标板是 ESP32-S3 N16R8：16 MB Quad Flash + 8 MB Octal PSRAM。屏幕是物理 800×480、16 位 RGB565 并行输出，不是原工程的 ST7789 SPI 屏。竖屏是在物理扫描面上做软件 rotation，不改动 RGB 总线引脚或面板时序。

工程使用：

- Flash 启动：DIO 80 MHz。
- PSRAM：OPI 80 MHz。
- RGB 面板原生尺寸：800×480。
- 软件 rotation 后逻辑画布：480×800，竖屏。
- 像素时钟：12.5 MHz。
- C 版同步极性：HSYNC / VSYNC 空闲高电平。
- 水平时序：前沿 8 / 脉宽 4 / 后沿 8。
- 垂直时序：前沿 8 / 脉宽 4 / 后沿 8。
- 单帧 RGB565 缓冲：800×480×2 = 768,000 字节，放在 PSRAM。rotation 只改变逻辑坐标，不改变这个容量。
- 背光：GPIO2，高电平点亮。

RGB 屏信号由板内固定的 GPIO1/3/4/5/6/7/8/9/14/15/16/21/39/40/41/42/45/46/47/48 驱动。GPIO2 是屏幕背光，不是独立业务 LED。

## GT911 触摸

| GT911 信号 | ESP32-8048S043C |
|---|---:|
| SDA | GPIO19 |
| SCL | GPIO20 |
| RESET | GPIO38，低有效 |
| INT | 不使用；不依赖 GPIO18/R17 |

初始化策略：

- I²C 固定 100 kHz，正常运行每 12 ms 轮询一次状态寄存器 `0x814E`。
- 1 秒业务长按阈值为 1,000 ms；只有最新触摸样本不超过 60 ms、且移动不超过 28 个逻辑像素时才继续累计，连续 300 ms 收不到触摸样本则按释放/异常处理。
- GPIO38 对 GT911 做低电平复位，释放后等待控制器就绪。
- 每次启动依次尝试 7-bit 地址 `0x5D` 和 `0x14`。仅当 `0x8140` 产品 ID 前三字节严格等于 ASCII `911` 时才接受该地址，不把普通 I²C ACK 当成有效 GT911。
- INT 线无论 R17 是否焊接都不参与业务，不安装触摸中断。
- 触摸包使用 `0x814E` data-ready/点数和 `0x814F` 起始的点数据，每包成功消费后向 `0x814E` 写 0 清状态。

本次实机启动已识别：

```text
address=0x5D
product=911
firmware=0x1060
reported/effective raw range=480x272
```

GT911 的 480×272 原始坐标会先自动归一化到 RGB 面板的物理 800×480 坐标，然后按与界面一致的 `rotation=1` 转成 480×800 逻辑坐标：

```text
logicalX = physicalY
logicalY = 799 - physicalX
```

除启动日志外，实机手指测试已确认当前坐标方向正确，并通过“下一任务”、问题页进入/取消、品质 PASS 选择和 1,000 ms 静止长按。四个边角的逐点坐标日志仍未单独留档，因此不将“方向正确”扩大表述为“边角校准已完整验收”。

## 触摸业务操作

### 任务页

页面有三个独立按钮：

- 点击“上报问题”：进入问题选择页。
- 点击“下一任务”：切换到下一项任务。
- 点击“完工确认”：进入品质选择页。

### 问题选择页

- 点击“有坏件 / 缺材料 / 机器坏 / 有危险”中的一张问题卡进行选择。
- 点击“取消”：立即返回任务页，不发出正式业务事件。
- 在“长按1秒确认”区域持续按住 1 秒：提交 `EXCEPTION_RAISED` 并进入锁定页。
- 普通点击确认区只会提示需要长按，不会误提交。

### 品质选择页

- 点击“合格”或“不合格”完成当前选择。
- 点击“取消”：立即返回任务页，不发出正式业务事件。
- 在“长按1秒提交”区域持续按住 1 秒：提交当前品质结果。
- 尚未选择合格/不合格时，确认区不会提交，而会提示先完成选择。

### 锁定页

- 演示模式下，在“长按8秒演示复位”区域持续按住 8 秒可回到任务页。
- 这是本地台架演示能力，不是正式问题解决事件。
- 正式上线前必须将 `DEMO_MODE` 改为 `false`，由后台权限事件解除锁定。

## 屏内状态灯

状态灯是界面右上角的屏内动画指示，不驱动任何外接 LED。

| 业务状态 | 屏内状态灯 |
|---|---|
| 正常生产 | 绿灯常亮 |
| 问题选择，尚未上报 | 黄灯慢闪 |
| 品质选择，尚未提交 | 黄灯双脉冲 |
| 问题已上报或品质不合格锁定 | 红灯快闪 |
| 完成当前一件 | 绿灯双闪 |

串口 `# FLOW ... led=...` 中保留了 `led` 字段名以兼容原业务日志，但它现在表示屏内状态灯，不代表 GPIO LED。

## 编译和上传

需要 PlatformIO Core。在项目根目录执行：

```bash
pio run
pio run -t upload --upload-port /dev/cu.usbserial-XXX
pio device monitor --port /dev/cu.usbserial-XXX --baud 115200
```

`platformio.ini` 已锁定 Arduino-ESP32 3.1.3 / ESP-IDF 5.3.2 对应的 pioarduino 平台，并锁定 Arduino_GFX 1.6.7 和 U8g2 2.36.18。上传速率固定为 115200，是因为这块板上的 CH340 在本次验证中使用更高速率出现了丢包。

```text
Flash: 1,451,456 / 3,145,728 bytes (46.1%)
firmware.bin: 1,451,824 bytes
Result: SUCCESS
```

## 串口事件

串口速率为 115200。正式业务动作每次输出一行 JSON，包含 `event_id`、`badge_id`、`worker_id`、`task_id`、`remaining`、`event_type`、`state`、`boot_id`、`device_sequence` 和 `device_ms`。

主要事件：

- `DEVICE_BOOT`
- `EXCEPTION_RAISED`
- `QUALITY_SUBMITTED`
- `PART_COMPLETED`
- `TASK_COMPLETED`
